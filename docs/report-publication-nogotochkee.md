## 4. Разбор одной поломки публикации

**Что видел.** После настройки автоматического развёртывания push в `main` перестал доходить до сервера. В списке доставок вебхука на GitHub — код `500`, при этом панель Coolify исправна, приложение работает, ручной Deploy разворачивает тот же коммит без единой ошибки. Первый push после создания вебхука прошёл успешно, следующие — нет.

**Чем оказалось.** В подробностях доставки GitHub написал причину дословно:

> POST https://159.194.255.54/webhooks/source/github/events/manual giving up after 1 attempt(s): tls: failed to verify certificate: x509: cannot validate certificate for 159.194.255.54 because it doesn't contain any IP SANs

То есть запрос уходил на `https://` с IP-адресом, а сертификат прокси на IP-адрес не выписан — проверить его нельзя. Сначала предполагалось, что дело в самом адресе вебхука, и он был возвращён на `http://`. Доставка всё равно падала с той же ошибкой. Проверка запросом показала настоящую причину: панель отвечает `307` и сама уводит с `http://` на `https://`, GitHub идёт по перенаправлению и упирается в тот же непроверяемый сертификат.

**Как починил.** Настоящее решение — дать панели доменное имя, на которое можно выпустить сертификат: запись `A` для `coolify.nogotochkee.ru` на сервер уже создана, остаётся указать домен в настройках экземпляра Coolify и переключить адрес вебхука на него. Пока этого нет, деплой запускается кнопкой в панели: на работу опубликованного сервиса это не влияет.

**Как убедился, что починилось:** **[заполнить после настройки домена панели]** — новый push должен дать доставку с кодом 200 и запуск развёртывания в панели.

**Чем эта поломка отличалась от тех, что случались на своём компьютере.** Она вообще не может случиться локально: на своём компьютере нет ни панели, ни вебхука, ни чужого сертификата — код просто запускается командой. Здесь же ошибка жила в стыке трёх участников: GitHub, прокси панели и сертификат. При этом ни один из них не считал себя сломанным: панель отвечала, приложение работало, логи были чистыми. Единственное место, где причина названа прямо, — журнал доставок на стороне GitHub.

Вторая поломка того же дня, для полноты: первое развёртывание падало с `fatal: Remote branch 1 not found in upstream origin`. В поле ветки в панели стояло `1` вместо `main`. Лог называл причину дословно, и правка заняла минуту.

## 5. Решение по персональным данным

**Режим работы сервиса:** учебный, на вымышленных и собственных данных.

**Что сделано, чтобы не собирать чужие данные:**

- **Плашка на главной**, выше первого экрана: «Учебный проект. Не вводите настоящие данные: имя, телефон и почту. Услуги, цены и мастера здесь тоже вымышленные — записаться в реальную студию через этот сервис нельзя.»
- **Отдельные предупреждения на экранах, где вводят данные:** на регистрации — «Учебный проект. Придумайте вымышленные имя, телефон и почту — настоящие вводить не нужно»; на шаге подтверждения записи — «Учебный проект. Запись тренировочная: студия по ней никого не ждёт. Оставляйте вымышленные данные».
- **Описание для поисковиков** говорит то же самое, плюс проставлен запрет индексации.
- **Кто заведён в базе.** Восемь учётных записей, живых людей среди них нет, кроме владельца сервиса. Администратор — владелец, вход по собственной почте. Демо-данные: три мастера (Анна Ковалева, Марина Орлова, Елена Смирнова), администратор `admin@nogotochkee.ru` и три клиентки (Ирина Петрова, Ольга Соколова, Дарья Волкова) — лица вымышленные, почты в домене сервиса, телефоны из ряда `+7 921 000-00-0X`. Телефон и адрес студии вымышленные: `+7 812 000-00-00`, Цветочная ул., 16.
- **Фотографии** — стоковые снимки с Unsplash под их бесплатной лицензией; авторы перечислены в `web/img/CREDITS.md`. Это не работы мастеров студии и не её интерьер, о чём сказано там же.
- **Общего пароля у демо-учёток нет:** каждой выдаётся свой случайный, он печатается один раз при загрузке данных и нигде не сохраняется.
- **Кому давал адрес:** **[заполнить]** — если ссылку никому не давали и живых клиентов не приглашали, так и написать.

**Что будет с сервером и данными после защиты:** **[заполнить]** — когда удаляется сервер (именно удаляется, а не выключается: тарификация посуточная), что делаете с файлом базы (скачать копию до удаления) и с доменом `nogotochkee.ru` (продлевать или дать освободиться). Отдельно стоит перевыпустить секрет приложения Яндекса и секрет вебхука: они назывались в переписке.

Обязанностей оператора персональных данных не возникает: сервис работал на вымышленных и собственных данных, чужих настоящих в базу не попадало.
