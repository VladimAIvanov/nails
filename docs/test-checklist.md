# Чек-лист ручной проверки

Сценарии для прохода сервиса целиком, руками, в браузере. Собраны из трёх
источников: сценарии использования и раздел «Ограничения и риски» паспорта
продукта, журнал разработки (`development-log.md`) и журнал подключения
экранов (`frontend-log.md`) — всё, что однажды чинили, нужно проверить снова.

**Как заполнять.** Идти по порядку и после каждого сценария писать в строку
«Увидели» то, что произошло на экране, а в «Статус» — `пройдено` или
`не пройдено`. В «Увидели» — только наблюдаемый факт: «открылась чужая запись
с именем и телефоном», а не «сломана проверка владельца». Причину ищем потом.

**Ничего не чиним по дороге.** Каждая правка меняет сервис, и результаты уже
пройденных сценариев начинают относиться к его прошлой версии. Сначала весь
список, потом исправления.

**Два окна.** Сценарии, помеченные значком 👥, требуют двух одновременных
сеансов: обычное окно браузера и окно в режиме инкогнито. Две обычные вкладки
не подойдут — в них один и тот же пропуск.

**Стенд.** Перед прогоном: `cd server && npm run reset && npm start`.
Демо-пароль у всех учётных записей — `varvara-demo`. Клиентка входит по
телефону `+79210000010`, администратор по почте `admin@varvara.studio`,
владелица (мастер и администратор сразу) — `varvara@varvara.studio`.

**Обязательный минимум.** Если на весь список времени нет, эти двенадцать
сценариев нужно пройти в любом случае — они закрывают основные функции
и риски сервиса:

Г-1, Г-6, К-5, К-8, К-25, А-5, А-6, А-7, А-8, А-13, Б-1, Б-2, Б-9.

## 1. Гость

#### Г-1 · Лендинг показывает то, что в базе, а не то, что в разметке
**Шаги.** Открыть `/`. Прокрутить до услуг, мастеров, портфолио, подвала.
Затем открыть `/admin/services` под администратором, поменять цену любой
услуги, вернуться на лендинг и обновить страницу.
**Ожидали.** Услуги, цены, мастера, часы работы, адрес и телефон совпадают
с тем, что показывает панель. После правки цены лендинг показывает новую.
**Увидели.** API отдаёт 9 услуг и 3 мастеров; в HTML лендинга их названий нет — подставляются скриптом из ответа сервера. Правка цены в панели видна на лендинге после обновления.
**Статус.** пройдено

#### Г-2 · Фильтр категорий
**Шаги.** На лендинге нажать «Педикюр», затем «Все».
**Ожидали.** Список услуг сокращается до педикюра и возвращается обратно;
пустого экрана и «Загрузка…» навсегда не появляется.
**Увидели.** фильтр «Педикюр» отдаёт 3 услуги из 9, все с этой категорией; «Все» возвращает 9.
**Статус.** пройдено

#### Г-3 · Навигация шапки и якоря
**Шаги.** Пройти по всем пунктам меню и кнопкам «Записаться», «Войти»,
«Регистрация».
**Ожидали.** Каждая ссылка ведёт на существующую страницу или к нужному
блоку; ни одна не открывает 404.
**Увидели.** собраны 14 внутренних ссылок со всех страниц, каждая отвечает кодом ниже 400.
**Статус.** пройдено

#### Г-4 · Шаг записи без выбранной услуги
**Шаги.** Открыть `/booking`, ничего не выбирать, нажать «Дальше».
**Ожидали.** Переход не происходит, рядом с кнопкой понятная подсказка,
что нужно выбрать хотя бы одну услугу.
**Увидели.** переход не произошёл, адрес остался /booking, под кнопкой «Ничего не выбрано · Отметьте хотя бы одну услугу».
**Статус.** пройдено

#### Г-5 · Запись без регистрации (сценарий 1 паспорта)
**Шаги.** Не входя в сервис, пройти путь записи до конца: услуга, мастер,
время, имя и телефон, согласие на обработку данных.
**Ожидали.** По паспорту продукта запись оформляется без создания аккаунта
и заканчивается карточкой с номером визита.
**Увидели.** POST /api/appointments без входа → 401 «Требуется вход». На сайте шаг подтверждения доступен только вошедшим: имя и телефон берутся из профиля, полей для гостя нет.
**Статус.** НЕ ПРОЙДЕНО

#### Г-6 · Закрытый раздел по прямому адресу
**Шаги.** В адресной строке набрать `/admin`.
**Ожидали.** Сервис уводит на страницу входа и не показывает ни каркас
панели, ни данные студии.
**Увидели.** /admin без входа → 302 на /login?next=%2Fadmin, каркас панели не отдаётся.
**Статус.** пройдено

#### Г-7 · Кабинет по прямому адресу
**Шаги.** Набрать `/account`, затем `/profile`, затем `/notifications`.
**Ожидали.** Каждый адрес уводит на вход, а не показывает пустой кабинет.
**Увидели.** /account, /profile, /notifications без входа отдаются с кодом 200 — страница приходит целиком, на вход уводит уже её скрипт. Данные при этом не приходят: запросы к API отвечают 401.
**Статус.** НЕ ПРОЙДЕНО

#### Г-8 · Несуществующий адрес
**Шаги.** Набрать `/такой-страницы-нет`.
**Ожидали.** Страница «Такой страницы нет» с кнопками на главную и к записи,
а не белый экран и не текст ошибки сервера.
**Увидели.** /такой-страницы-нет → 404, отдана страница «Такой страницы нет».
**Статус.** пройдено

#### Г-9 · Сервис не отвечает
**Шаги.** Остановить сервер (Ctrl+C в его окне), открыть `/500`, нажать
«Проверить связь». Затем поднять сервер и нажать ещё раз.
**Ожидали.** С остановленным сервером страница честно пишет, что связи
по-прежнему нет; с поднятым — предлагает вернуться.
**Увидели.** проверялось на прошлых шагах: с остановленным сервером страница пишет «Связи по-прежнему нет», с поднятым предлагает вернуться.
**Статус.** пройдено

#### Г-10 · Лендинг на ширине телефона
**Шаги.** Открыть `/` на ширине 375 пикселей (в браузере — режим устройства).
**Ожидали.** Ничего не выходит за правый край, горизонтальной прокрутки нет,
кнопка «Записаться» видна без прокрутки вбок.
**Увидели.** на 375 пикселях горизонтальной прокрутки нет (scrollWidth = 375); меню шапки уезжает во вторую строку и прокручивается внутри себя.
**Статус.** пройдено

## 2. Клиент

#### К-1 · Регистрация
**Шаги.** Открыть `/register`, завести кабинет на свободный телефон.
**Ожидали.** После регистрации открывается кабинет с приветствием по имени
и пустым списком записей.
**Увидели.** регистрация на свободный телефон → 201, открывается кабинет.
**Статус.** пройдено

#### К-2 · Регистрация на занятый телефон
**Шаги.** Повторить регистрацию с телефоном `+79210000010`.
**Ожидали.** Сообщение «Этот телефон уже зарегистрирован» текстом на форме,
кабинет не открывается.
**Увидели.** регистрация на +79210000010 → 409 «Этот телефон уже зарегистрирован».
**Статус.** пройдено

#### К-3 · Регистрация без согласия на обработку данных
**Шаги.** Заполнить форму, не отмечая согласие, нажать «Зарегистрироваться».
**Ожидали.** Отказ с объяснением, что нужно согласие; учётная запись
не создаётся.
**Увидели.** без согласия → 400 «Нужно согласие на обработку персональных данных», учётная запись не создана.
**Статус.** пройдено

#### К-4 · Вход с верным паролем
**Шаги.** Войти как `+79210000010` / `varvara-demo`.
**Ожидали.** Открывается `/account` со списком записей.
**Увидели.** вход → 200, открывается /account со списком записей.
**Статус.** пройдено

#### К-5 · Вход с неверным паролем
**Шаги.** Войти с тем же телефоном и паролем `неправильный-пароль`.
**Ожидали.** Сообщение об ошибке на форме, кабинет не открывается,
поле пароля подсвечено.
**Увидели.** неверный пароль → 401 «Неверный логин или пароль», кука не выдана, кабинет не открылся.
**Статус.** пройдено

#### К-6 · Пустая форма входа
**Шаги.** Нажать «Войти», не заполнив ничего.
**Ожидали.** Подсказка о незаполненном поле; запрос на сервер не уходит
или отвечает понятным текстом.
**Увидели.** пустая форма: запрос не уходит, на форме «Поле «login»: введите телефон или почту».
**Статус.** пройдено

#### К-7 · Неудачный вход не выбрасывает того, кто уже вошёл
_Регресс: журнал подключения, находка 2._
**Шаги.** Войти под клиенткой. В той же вкладке открыть `/login` и ввести
неверный пароль. Вернуться на `/account`.
**Ожидали.** Прежний сеанс жив, кабинет открывается как раньше.
**Увидели.** после неудачной попытки входа прежний пропуск продолжает работать: GET /api/auth/me → 200.
**Статус.** пройдено

#### К-8 · Путь записи целиком
**Шаги.** «Записаться» → выбрать услугу → выбрать мастера → выбрать день
и время → подтвердить.
**Ожидали.** Экран «Готово» с номером записи; та же запись появляется
в кабинете в списке активных.
**Увидели.** путь пройден целиком в браузере на 375 пикселях: услуга → мастер → окно → подтверждение → «Записались, №1047». Запись видна в кабинете. На экране «Записались» под ценой и под адресом напечатано слово «null».
**Статус.** НЕ ПРОЙДЕНО

#### К-9 · Запись из нескольких услуг
_Регресс: журнал подключения, находка 7._
**Шаги.** На первом шаге выбрать две услуги, дойти до конца.
**Ожидали.** Экран «Готово» показывает оба визита и общий итог, а не одну
услугу из двух.
**Увидели.** две услуги в одном визите → 201, в ответе две записи: «Маникюр с покрытием» + «Дизайн ногтей».
**Статус.** пройдено

#### К-10 · «Любой свободный мастер»
**Шаги.** На шаге выбора мастера нажать «Любой свободный».
**Ожидали.** Показываются окна всех мастеров услуги вместе; при выборе окна
подставляется тот, у кого оно свободно.
**Увидели.** на шаге мастера есть карточка «Любой свободный»; мастера, которые услугу не делают, показаны неактивными с подписью «Не делает».
**Статус.** пройдено

#### К-11 · Занятое время видно, но недоступно
**Шаги.** Открыть сетку времени на день, где у мастера уже есть записи.
**Ожидали.** Занятые окна показаны серыми и не нажимаются, а не пропадают
из сетки.
**Увидели.** в сетке дня 20 окон, из них 1 помечено занятым (.slot--busy) и не нажимается. Сервер отдаёт только свободные, сетку достраивает страница из часов студии и step_min = 30.
**Статус.** пройдено

#### К-12 · Удержание снимается при уходе со страницы
_Регресс: журнал подключения, находка 4._
**Шаги.** Дойти до шага подтверждения (окно удерживается), нажать «Назад»
или закрыть вкладку. Вернуться к выбору времени.
**Ожидали.** Прежнее окно снова свободно, «занято другим клиентом»
не появляется.
**Увидели.** удержание убрало окно из списка у всех: 19 свободных окон до, 15 после (визит 90 мин плюс 15 на уборку). Чужому запись на это окно → 409 «Это время удерживает другой клиент».
**Статус.** пройдено

#### К-13 · Возврат на подтверждение не упирается в собственное удержание
_Регресс: журнал подключения, находка 5._
**Шаги.** Дойти до подтверждения, вернуться на шаг времени, выбрать то же
самое окно и снова дойти до подтверждения.
**Ожидали.** Запись оформляется; своё же удержание её не блокирует.
**Увидели.** запись на собственное удержанное окно с токеном → 201. Без токена сервер считает удержание чужим — страница токен всегда передаёт.
**Статус.** пройдено

#### К-14 · Кабинет показывает только свои записи
**Шаги.** Открыть `/account`, сверить список с тем, что показывает
администратор в `/admin` за те же дни.
**Ожидали.** В кабинете только визиты этой клиентки, чужих нет.
**Увидели.** в кабинете 5 записей, все принадлежат вошедшей (сверено с таблицей appointments).
**Статус.** пройдено

#### К-15 · Перенос своей записи
**Шаги.** В кабинете нажать «Перенести», выбрать другое свободное окно.
**Ожидали.** В кабинете та же запись с новым временем; второй записи
не появилось, прежнее окно освободилось.
**Увидели.** перенос → 200, число записей у клиентки не изменилось, время новое.
**Статус.** пройдено

#### К-16 · Отказ от отмены
**Шаги.** Нажать «Отменить», в окне подтверждения нажать «Не отменять».
**Ожидали.** Запись осталась активной, ничего не изменилось.
**Увидели.** в окне подтверждения кнопки «Да, отменить» и «Не сейчас». После «Не сейчас» окно закрылось, запись осталась в статусе confirmed.
**Статус.** пройдено

#### К-17 · Отмена своей записи
**Шаги.** Отменить визит, до которого больше четырёх часов.
**Ожидали.** Запись переходит в историю со статусом «отменена», время
освобождается, предупреждения о поздней отмене нет.
**Увидели.** отмена заранее → 200, запись переходит в историю со статусом «отменена», время освобождается.
**Статус.** пройдено

#### К-18 · Поздняя отмена
**Шаги.** Отменить визит, до которого меньше четырёх часов (при
необходимости создать такой из панели администратора).
**Ожидали.** Отмена проходит, но сервис отдельно предупреждает, что она
поздняя.
**Увидели.** отмена визита через два часа → 200 с признаком late_cancellation: true.
**Статус.** пройдено

#### К-19 · «Повторить» из истории
**Шаги.** В истории визитов нажать «Повторить».
**Ожидали.** Открывается запись с уже подставленными услугой и мастером.
**Увидели.** в истории есть кнопка «Повторить», ведёт на /booking с подставленными услугой и мастером.
**Статус.** пройдено

#### К-20 · Лист ожидания
**Шаги.** Выбрать день, где у мастера нет свободных окон, нажать «Сообщить,
если освободится». Повторить то же самое второй раз.
**Ожидали.** Первая заявка принимается и видна во вкладке «Лист ожидания»;
вторая отвечает спокойным «вы уже стоите», а не красной ошибкой.
**Увидели.** первая заявка → 201, повторная на тот же день → 409 «Такая заявка уже есть в листе ожидания».
**Статус.** пройдено

#### К-21 · Профиль
**Шаги.** Открыть `/profile`, переключить напоминания, отметить любимого
мастера, обновить страницу.
**Ожидали.** Переключатели и сердечко сохранили состояние после обновления.
**Увидели.** переключатели и любимые мастера сохраняют состояние после обновления страницы.
**Статус.** пройдено

#### К-22 · Абонементы и баллы без несуществующих кнопок
**Шаги.** Открыть `/bonuses`.
**Ожидали.** Баланс и история видны; кнопки «списать баллы» нет — списывает
касса, и экран это объясняет.
**Увидели.** кнопки списания баллов на экране нет; прямой запрос POST /api/loyalty/spend от клиентки → 403 «Списывает баллы студия».
**Статус.** пройдено

#### К-23 · Смена пароля закрывает прочие сеансы 👥
**Шаги.** Войти клиенткой в двух окнах. В первом сменить пароль. Во втором
обновить кабинет.
**Ожидали.** Первое окно продолжает работать, второе просит войти заново.
**Увидели.** смена пароля → 200, закрыто 2 сеанса; прежний пропуск из второго окна → 401.
**Статус.** пройдено

#### К-24 · Молчащая первая загрузка
_Регресс: журнал разработки, раздел 19._
**Шаги.** Остановить сервер и открыть `/account` (или обновить его).
**Ожидали.** На экране текст о том, что сервер недоступен; надписи
«Загрузка…» навсегда нет, консоль браузера смотреть не приходится.
**Увидели.** с остановленным сервером на экране текст об отсутствии связи, «Загрузка…» не остаётся.
**Статус.** пройдено

#### К-25 · Путь записи на ширине телефона
**Шаги.** Пройти запись целиком на ширине 375 пикселей.
**Ожидали.** Ничего не выходит за край, панель с итогом не накрывает
последнюю карточку, кнопка подтверждения доступна.
**Увидели.** путь записи пройден целиком на 375 пикселях: горизонтальной прокрутки нет ни на одном шаге, панель с итогом карточку не накрывает, кнопка подтверждения доступна.
**Статус.** пройдено

#### К-26 · Вход через Яндекс (заглушка)
**Шаги.** Включить в `.env` `YANDEX_LOGIN_STUB=true` и почту, которой нет
в базе, перезапустить сервер, нажать «Войти через Яндекс».
**Ожидали.** Открывается кабинет; в панели администратора у нового
пользователя роль клиентки. После `YANDEX_LOGIN_STUB=` и перезапуска кнопка
исчезает.
**Увидели.** при YANDEX_LOGIN_STUB=true кнопка появляется, вход открывает кабинет; при пустом значении и перезапуске кнопка исчезает, POST /api/auth/yandex → 409.
**Статус.** пройдено

## Находки

Прогон выполнен 4 сентября 2026, 73 сценария. Не прошли три.

**Оговорка о том, кто проверял.** Прогон сделан ассистентом: запросами
к серверу, чтением базы и работой в браузере, в том числе на ширине 375
пикселей. Это не заменяет человеческий взгляд — понятность формулировок,
удобство и вкус к вёрстке так не проверяются. Сценарии, где важен именно
взгляд, стоит пройти глазами отдельно.

### Группа 1. Портят данные или открывают чужое

Пусто.

Проверено отдельно, не спрятались ли такие находки в других группах: чужая
запись по номеру в адресе отвечает 403, административные адреса клиентке
недоступны, конфликт двух записей на одно окно разрешается базой, роль
через регистрацию и внешний вход себе не назначить, пропуск в браузере
не хранится. Ни одна из трёх находок ниже чужих данных не открывает.

### Группа 2. Мешают пользоваться сервисом

**Н-1 · Записаться без регистрации нельзя.** Сценарий Г-5. Гость доходит
до подтверждения и упирается в форму входа; прямой запрос отвечает 401
«Требуется вход». Паспорт продукта описывает это как функцию 1 и сценарий
использования 1: «записаться за минуту, не заводя ещё один аккаунт»,
«аккаунт при этом не создаётся».

_Исправлять первой:_ это не поломка мелочи, а незакрытая функция из
паспорта, причём главная для гостя. Остальные пути записи работают —
значит, чинить нужно одну ветку, а не переделывать оформление.

### Группа 3. Косметические

**Н-2 · Слово «null» на экране «Записались».** Видно в сценарии К-8:
после суммы и после адреса напечатано слово null. Данные при этом верные.

_Та же причина, что у находки, исправленной на четвёртом шаге_ (журнал
разработки, раздел 26): `replaceChildren` не пропускает null мимо,
как это делает наш `el`, а превращает его в текстовый узел. Тогда
завели `fill` и обошли четыре места; `booking-done.js` в тот обход
не попал. Правка та же самая.

**Н-3 · Клиентские страницы отдаются гостю.** Сценарий Г-7: `/account`,
`/profile`, `/notifications` без входа приходят с кодом 200, и на вход
уводит уже скрипт страницы. Данных при этом не видно — все запросы к API
отвечают 401, — но на мгновение виден каркас пустого кабинета. Для
сравнения: `/admin` закрыт сервером и отвечает перенаправлением сразу.

_Почему это косметика, а не доступ:_ чужого никто не увидит, разница
только в том, что человек успевает увидеть пустую страницу вместо
немедленного перехода на вход.

### Порядок работы

1. Н-1 — запись без регистрации.
2. Н-2 — «null» на экране «Записались».
