# Отчёт о тестировании сервиса

**Проект:** «Ноготочки», сервис онлайн-записи в бьюти-студию (<https://nogotochkee.ru>)

Проверки выполнены 15–16.09.2026 на локальном сервере с базой из демо-данных, в браузере на ширине телефона (375 px) и сквозным скриптом `server/scripts/e2e-scenarios.mjs`, который проходит те же сценарии через API на отдельной временной базе. Полный чек-лист со всеми 28 проверками — [docs/test-scenarios.md](test-scenarios.md).

## 1. Три сценария проверки

**Сценарий 1. Доступ к админ-панели**

- Роль пользователя: обычный клиент (Ольга Соколова, `+79210000011`).
- Действие: войти клиенткой и вручную открыть адрес `/admin`.
- Ожидаемый результат: панель не открывается, сервис показывает понятное сообщение о недостатке прав, содержимое панели не загружается.

**Сценарий 2. Запись двух клиентов на один слот**

- Роли пользователей: две клиентки — Ирина Петрова и Ольга Соколова.
- Действие: обе выбирают одно и то же свободное окно у Елены Смирновой. Первая подтверждает запись, затем то же окно пытается подтвердить вторая.
- Ожидаемый результат: запись первой создаётся, вторая получает отказ, занятое время исчезает из свободных окон.

**Сценарий 3. Отмена записи администратором**

- Роли пользователей: администратор и клиентка Ольга Соколова.
- Действие: администратор отменяет запись клиентки из панели `/admin`.
- Ожидаемый результат: в кабинете клиентки запись помечена как отменённая, в уведомлениях появляется сообщение об отмене, освободившееся время снова доступно для записи.

## 2. Проверка доступа к админ-панели

- **Что сделали:** вошли клиенткой Ольгой Соколовой и вручную открыли `/admin`, затем `/admin/services`.
- **Что появилось на экране:** «ОШИБКА 403. Этот раздел только для администраторов. Вы вошли, но прав на панель студии у вашей учётной записи нет. Всё, что нужно для записи и просмотра своих визитов, — в личном кабинете.» Ниже кнопки «Мои записи», «Записаться», «На главную».
- **Что произошло:** сервер отказал в доступе и вернул код 403 вместо страницы панели.
- **Как определили:** страница отказа пришла сразу, каркас панели не появился ни на мгновение. В исходном коде страницы подключён только `forbidden.js` — скрипты панели (`admin-appointments.js`, `admin-services.js`) сервер не отдал вовсе. Запросы к данным панели под той же клиенткой (`/api/admin/appointments`) отвечают 403. Ссылки «Админ-панель» в шапке у клиентки нет.
- **Вывод:** доступ закрыт на сервере — закрыты и страница, и данные, а не только спрятана ссылка в интерфейсе. На опубликованной версии проверено, что гостя с `/admin` уводит на страницу входа (302 → `/login?next=/admin`).

## 3. Проверка записи двух клиентов на один слот

- **Имя второго клиента:** Ольга Соколова (`+79210000011`).
- **Время слота:** вторник, 22 сентября, 10:00, мастер Елена Смирнова, услуга «Ламинирование бровей».
- **Что сделали:** обе клиентки открыли выбор времени и увидели окно 10:00 свободным. Ирина Петрова подтвердила запись первой. Ольга после этого нажала «Далее» на выбранном окне и дошла до экрана подтверждения.
- **Что увидел второй клиент:** «Так нельзя. Это время уже занято или удерживается», ниже — «Ближайшее свободное время:» с кнопками 11:00, 11:30, 12:00, 12:30, 13:00. Кнопка «Подтвердить запись» стала неактивной.
- **Что произошло со списком свободного времени:** окно 10:00 и пересекающиеся с визитом окна пропали из списка свободных. При проверке через API: первый запрос — 201, второй на то же время — 409 «Это время только что заняли. Выберите другое окно» и пять ближайших окон в ответе.
- **Вывод:** двум клиенткам записаться на один слот не удалось. Запрет держится не интерфейсом, а базой: пересечение действующих записей одного мастера отклоняет триггер, поэтому отказ срабатывает и при одновременных запросах. Дополнительно проверен более ранний шаг: если обе дошли до экрана подтверждения, окно удерживается за первой, вторая получает отказ уже на удержании.

## 4. Проверка отмены записи

- **Что сделал администратор:** отменил запись Ольги Соколовой на четверг, 17 сентября, 12:00 (ламинирование бровей, Марина Орлова), указав причину «проверка: отмена администратором».
- **Что произошло с записью в кабинете клиента:** запись осталась в кабинете и переехала из вкладки «Активные» во вкладку «История» с пометкой «Отменена». Счётчики вкладок изменились: «Активные 1 → 0», «История 0 → 1».
- **Счётчик уведомлений:** до отмены уведомлений не было, после отмены в шапке рядом с пунктом «Уведомления» появился значок «1», на странице — «Непрочитанных: 1 сообщение».
- **Текст уведомления:** «Визит отменён. Визит четверг, 17 сентября, 12:00 отменён студией. Причина: проверка: отмена администратором.» Рядом кнопка «Запись № 1043».
- **Оценка уведомления:** из текста понятно, что произошло, какого визита это касается и почему. Дата, время и причина названы прямо, номер записи рядом. Освободившееся время сразу вернулось в список свободных окон Марины на 17 сентября.

## 5. Разбор поломки

- **Что увидели.** На экране выбора времени, кроме доступных окон, показывались серые неактивные кнопки: у Анны Ковалевой со сменой до 18:00 предлагались 17:00, 17:30, 18:00 и 18:30, а в день с чужой записью на 10:00 — кнопки 10:00, 10:30 и 11:00 с подсказкой «Это время уже занято». По техническому заданию такие слоты не должны отображаться клиенту вовсе, и два контрольных сценария из задания на экране не проходили, хотя через API считались верно.
- **В чём оказалась причина.** Сервер отдаёт только свободные окна — это подтвердилось запросом к `/api/masters/2/slots`: в ответе было 14 окон, последнее 16:30. Значит дело не в расчёте, а в показе. В файле `web/js/booking-time.js` нашлась функция `fullGrid`: она достраивала сетку дня по часам **студии** (10:00–20:00) и все точки, которых не было в ответе сервера, рисовала неактивными. График мастера, блокировки и чужие записи она не различала — отсюда и окна после конца смены, и чужое занятое время.
- **Как исправили.** Убрали достройку сетки: экран показывает ровно те окна, которые вернул сервер, разложенные по утру, дню и вечеру. Заодно вычистили подсказку «Это время уже занято», которая вводила в заблуждение.
- **Как проверили результат.** Повторно прошли оба контрольных сценария. Анна Ковалева, среда, маникюр: на экране 11:30 … 16:30, кнопок 10:00–11:00 и после 16:30 нет — совпадает с ответом API. Марина Орлова, пятница, ламинирование: 11:00 … 14:00 и 17:00 … 19:00, время блокировки 15:00–17:00 не показывается. Затем прогнали весь сквозной набор сценариев: 28 из 28 пройдены, поведение остальных экранов не изменилось.

**Ещё две проблемы, найденные тем же заходом** (разобраны в чек-листе):

- набор услуг, который не делает ни один мастер, заводил в тупик: вариант «Любой свободный» оставался активным, а на следующем экране показывалась ошибка «Нет связи с сервером», хотя связь была. Теперь вариант неактивен, а подсказка предлагает убрать одну из услуг;
- главная страница была шире экрана телефона из-за колонок галереи; после правки ширина страницы равна ширине экрана.
