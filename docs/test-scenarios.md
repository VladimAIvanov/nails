# Сценарное тестирование сервиса «Ноготочки»

Чек-лист этапа 4 проектной работы: ключевые сценарии клиента и администратора, три контрольных сценария, ожидаемый и фактический результат. Сначала пройден весь чек-лист и записан результат, затем исправлены найденные проблемы и выполнена повторная проверка.

## Как проверялось

| Часть | Как | Где |
|---|---|---|
| Сценарии через API | скрипт `server/scripts/e2e-scenarios.mjs` поднимает отдельный сервер на временной базе, загружает демо-данные и проходит сценарии так же, как их проходят страницы | сырые результаты — `server/scripts/e2e-result.json` |
| Интерфейс | браузер, ширина 375 px (телефон): страницы, переходы, отображение | локальный сервер `http://localhost:3000` |

Запуск проверки через API из папки `server`:

```bash
node scripts/e2e-scenarios.mjs
```

## Найденные проблемы и исправления

### U1. На экране выбора времени видно время, на которое записаться нельзя

- **Что увидели.** Анна, среда, маникюр 1,5 ч: кроме окон 10:00–16:30 внизу серые кнопки 17:00, 17:30, 18:00, 18:30, хотя смена Анны кончается в 18:00. В день, когда у Анны запись на 10:00, серыми видны 10:00–11:00. Требование паспорта и контрольные сценарии 1–2: такое время клиенту не показывается.
- **Причина.** Сервер отдаёт только свободные окна, а экран (`web/js/booking-time.js`, функция `fullGrid`) достраивал сетку дня по часам **студии** 10:00–20:00 и все недостающие точки рисовал неактивными с подписью «Это время уже занято». Часы мастера, блокировки и чужие записи экран не различал.
- **Исправление.** Сетка больше не достраивается: экран показывает ровно те окна, что вернул сервер, разложенные по утру, дню и вечеру (`freePoints`).
- **Повторная проверка.** Анна, среда: на экране 10:00 … 16:30, после 16:30 кнопок нет — совпадает с ответом API. Анна, день с записью на 10:00: первое окно 11:30, кнопок 10:00–11:00 нет.

### U2. Набор услуг, который не делает ни один мастер, заводит в тупик

- **Что увидели.** Выбраны «Маникюр и педикюр» и «Коррекция и окрашивание бровей». Все мастера неактивны, но «Любой свободный» выбирается и «Далее» ведёт на экран времени с ошибкой «Нет связи с сервером. Ни один мастер не делает выбранный набор услуг».
- **Причина.** В `web/js/booking-master.js` карточка «Любой свободный» была активна всегда: проверка «есть ли мастер на весь набор» выполнялась только на следующем шаге, а ошибка показывалась как сетевая.
- **Исправление.** Если весь набор не делает ни один мастер, «Любой свободный» неактивен с пояснением, кнопка «Далее» выключена, подсказка предлагает вернуться и убрать одну из услуг. Сохранённый ранее выбор «любой» сбрасывается.
- **Повторная проверка.** Тот же набор: «Любой свободный» неактивен, «Далее» выключена, клик по карточке ничего не выбирает, подсказка видна. Одна услуга (маникюр): «Любой свободный» выбирается, «Далее» активна.

### U3. Главная страница шире экрана телефона

- **Что увидели.** На ширине 375 px блок «Работы» заканчивался на 466 px, страница прокручивалась вбок.
- **Причина.** В `web/css/landing.css` колонки галереи заданы как `repeat(2, 1fr)`. Нижняя граница `1fr` — ширина содержимого, а карточка с отступами 24 px и подписью «Наращивание, форма миндаль» не помещалась в половину экрана.
- **Исправление.** Колонки `minmax(0, 1fr)`, у карточки `min-width: 0`, на телефоне внутренние отступы 12 px, длинная подпись переносится.
- **Повторная проверка.** Ширина страницы 375 px, элементов за правым краем нет, колонки по 161,5 px.

### Новые находки прохода 3

- **U4. В окне переноса визит «мешает сам себе».** Запись Дарьи 14:00–16:30: в выборе нового времени нет 12:00–16:00, хотя после переноса это время свободно. Причина: расчёт окон считает занятым и время самой переносимой записи. Сервер такой перенос принимает (проверено через API: 14:00 → 16:00 проходит), не хватает только окон в списке. Касается и переноса из кабинета клиента.
  - **Исправление.** `GET /api/masters/:id/slots` принимает `exclude_appointment_id`: время этой записи не считается занятым. Исключить можно только свою запись (клиент — свою, мастер — к себе, администратор — любую), иначе 403: по разнице в окнах можно было бы узнать, когда записан другой человек. Параметр передают экран переноса у клиента и окно переноса в панели.
  - **Повторная проверка.** Запись Дарьи 16:30–19:00: в окне переноса теперь 11:00 … 16:30, включая 14:00–16:00 (раньше — только 11:00, 11:30, 16:30). В сквозном тесте (U4): своя запись — 200 и окна 14:00, 14:30; чужая — 403; гость — 403.
- **U5. Сырое время UTC в строке записи.** После переноса в панели написано «перенос с 2026-09-22T11:00:00Z на 2026-09-22T13:30:00Z», а по часам студии это 14:00 → 16:30. Причина: в журнал статусов пишется время в формате хранения, а панель выводит комментарий как есть.
  - **Исправление.** Комментарий к переносу пишется по часам студии («перенос с вторник, 29 сентября, 14:00 на …»); панель переводит в местное время и старые комментарии с форматом базы.
  - **Повторная проверка.** Старая запись Дарьи показывается как «перенос с 22.09 14:00 на 22.09 16:30»; в сквозном тесте (U5) новый комментарий без «…T…Z». Прогон — 28 из 28.

## Что пройти вручную

Под учётными записями из сидов (`SEED_SHOW_PASSWORDS=true npm run seed`):

1. Два окна браузера (второе — в режиме инкогнито), Ирина и Ольга, одно и то же окно у Елены Смирновой → подтвердить первой, затем второй. Ожидание: у второй отказ и список ближайших окон.
2. Клиентом открыть `/admin` вручную — страница «Раздел недоступен», ссылки «Админ-панель» в шапке нет.
3. Администратором перенести и отменить запись в `/admin`, затем проверить кабинет клиентки.
4. Кабинет, перенос и отмена из кабинета, админ-панель — на ширине телефона.
