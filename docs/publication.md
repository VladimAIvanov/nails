# Публикация сервиса «Ноготочки»

Инструкция к шагам 15–19 проектной работы. Стек тот же, что в модуле: VPS, панель Coolify, сборка по `docker-compose.yaml` из репозитория, HTTPS от Let's Encrypt, вход через Яндекс ID.

Что делает ассистент, а что — владелец сервиса:

| Шаг | Кто | Почему |
|---|---|---|
| 15. Подготовка к деплою | ассистент, локально | сборка контейнера, секреты, том, миграции проверяются на своём компьютере |
| 16. Развёртывание | владелец | нужен вход в панель Coolify на сервере |
| 17. Домен и HTTPS | владелец | нужен доступ к DNS домена и к панели |
| 18. Вход через Яндекс | владелец | нужен кабинет приложения на oauth.yandex.ru и живой Яндекс ID |
| 19. Финальная проверка | владелец (ассистент может пройти API-часть по адресу) | нужен повторный деплой в панели |

## Шаг 15. Подготовка к деплою

**Что уже есть в репозитории**

| Требование | Где | Как устроено |
|---|---|---|
| Проект собирается в контейнер | `Dockerfile` | `node:24-slim`, пояс Europe/Moscow, запуск от пользователя `node`, проверка здоровья `GET /api/health` |
| Секреты вне кода | `.env.example` — перечень, `.env` — локально, панель Coolify — на сервере | `.env`, ключи и сертификаты не попадают ни в git (`.gitignore`), ни в образ (`.dockerignore`) |
| База вне пересоздаваемого контейнера | `docker-compose.yaml` | именованный том `nogotochki-data` смонтирован в `/app/storage`, база — `/app/storage/nogotochki.db` |
| Миграции запускаются корректно | `server/src/index.js` | при каждом старте применяются новые миграции, применённые пропускаются (`schema_migrations`) |

**Секреты, которые задаются только в панели:** `ADMIN_EMAIL`, `ADMIN_PASSWORD` (не короче 8 знаков), `ADMIN_NAME` — первый администратор на чистой базе; `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`, `YANDEX_REDIRECT_URI` — вход через Яндекс. В `docker-compose.yaml` они намеренно не объявлены: строка вида `- X=${X:-}` присылает в контейнер пустое значение поверх заданного в панели.

**Проверка на своём компьютере** — раздел «Результат проверки шага 15» в конце документа.

## Шаг 16. Развёртывание на сервере

### Решение до начала: новое приложение

Сейчас на сервере работает приложение прошлой версии проекта: оно собирается из старого репозитория и держит базу на своём томе. Приложение «Ноготочек» заводится **отдельно**, из репозитория `VladimAIvanov/nails`:

- старое не ломается, пока новое не проверено;
- том у нового свой (`nogotochki-data`), старая база не затрагивается;
- старое приложение удаляется в панели после проверки нового, вместе с томом, если его данные не нужны.

### Что сделать в Coolify

1. **Projects → проект → + New → Private Repository (with GitHub App)** (или Public Repository, если репозиторий открыт) → репозиторий `VladimAIvanov/nails`, ветка `main`.
2. **Build Pack: Docker Compose**, путь к файлу — `/docker-compose.yaml`. Нажать **Continue** / **Load Compose File**: в списке появится сервис `app`.
3. **Environment Variables** приложения — добавить:
   - `ADMIN_EMAIL` — ваша почта;
   - `ADMIN_PASSWORD` — длинный пароль (не короче 8 знаков, сохраните его в менеджер паролей);
   - `ADMIN_NAME` — например, `Администратор студии` (необязательно).

   Переменные Яндекса — позже, на шаге 18.
4. **Persistent Storage** — проверить, что есть том для `/app/storage`. Coolify создаёт его сам из `docker-compose.yaml` и добавляет к имени свой префикс — это нормально.
5. Домен пока не указывать (шаг 17) — **Deploy**.
6. **Logs** развёртывания: сборка без ошибок. **Logs** приложения: строки `Миграции применены при запуске: 001…014` и `Сервис записи «Ноготочки» слушает …`, а также `Заведён администратор …`.
7. Демонстрационные данные (мастера, услуги, тестовые записи): **Terminal** контейнера `app` →

   ```sh
   SEED_SHOW_PASSWORDS=true node src/seed.js
   ```

   Пароли демо-учёток печатаются один раз — сохраните их. Сиды пересоздают записи и портфолио, поэтому запускать их нужно один раз, до проверки, а не после.

   Сиды заводят и своего администратора `admin@nogotochkee.ru`. Администратор из `ADMIN_EMAIL` при этом остаётся — входите под ним.

**Как проверить:** до подключения домена Coolify показывает у приложения временный адрес вида `http://<случайное-имя>.<IP>.sslip.io` — если его нет, переходите сразу к шагу 17 и проверяйте по домену. Главная открывается, в шапке «Ноготочки», в «Услугах» шесть услуг.

> Сервис в рабочем режиме **отказывается стартовать по открытому HTTP**, если TLS не завершает доверенный прокси. Прокси Coolify доверенный (`TRUST_PROXY=10.0.0.0/8` в `docker-compose.yaml`), поэтому за ним сервис стартует.

## Шаг 17. Домен и HTTPS

1. **DNS домена** (у регистратора): запись `A` для `@` и для `www` → IP вашего сервера. Если у домена есть запись `AAAA` на другой адрес — удалить. Распространение — от нескольких минут до часа; проверить: `nslookup <домен>` показывает IP сервера.
2. **Coolify → приложение → сервис `app` → Domains:** `https://<домен>:3000,https://www.<домен>:3000`.

   `:3000` — порт **внутри контейнера**, куда прокси отправляет запросы; в адресе сайта его не будет.
3. **Redeploy.** Сертификаты Let's Encrypt выпускаются сами в течение минуты.

**Как проверить:**

- `https://<домен>` открывается, в адресной строке замок;
- `http://<домен>` сам переходит на `https://`;
- `https://<домен>/api/health` отвечает `{"ok":true,…}`;
- после входа кука сеанса `nogotochki_session` с признаками `Secure`, `HttpOnly`, `SameSite=Lax` (DevTools → Application → Cookies). Без `Secure` сервер не узнал прокси — проверьте, что `TRUST_PROXY` не переопределён в панели.

## Шаг 18. Вход через Яндекс

1. **https://oauth.yandex.ru → Создать приложение → «Для авторизации пользователей»**. Название — `Ноготочки`.
2. **Платформа: веб-сервисы.** Redirect URI — строго `https://<домен>/api/auth/yandex/callback` (протокол, домен и путь буква в букву, без косой черты в конце).
3. **Доступы** — только два: «Доступ к адресу электронной почты» и «Доступ к логину, имени и фамилии, полу». Лишние права сервис не использует, а на экране согласия они отпугивают.
4. Скопировать **ClientID** и **Client secret**.
5. **Coolify → Environment Variables:** `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`, `YANDEX_REDIRECT_URI` (та же строка, что в кабинете Яндекса — скопировать, а не набирать). **Redeploy.**

**Как проверить:**

- `https://<домен>/api/studio` → `"external_login":["yandex"]`, на `/login` есть кнопка «Войти с Яндекс ID»;
- **первый вход:** в окне инкогнито нажать кнопку, согласиться — открывается кабинет;
- **повторный вход:** выйти и войти ещё раз — тот же кабинет;
- **нет дубликата:** Coolify → Terminal контейнера `app`:

  ```sh
  node --input-type=module -e "const {all}=await import('./src/db.js');console.table(all(\"SELECT id, email, role, provider FROM users WHERE provider='yandex'\"))"
  ```

  После двух входов — одна строка с вашей почтой.

Если почта Яндекс ID совпадает с `ADMIN_EMAIL`, вход привяжется к администратору (роль `admin` сохранится), а не заведёт клиента — это правильное поведение. Чтобы проверить именно нового пользователя, войдите Яндекс ID с другой почтой.

**Если кнопки нет:** Terminal → `env | grep YANDEX` — у всех трёх должны быть значения. Пустые значения — переменная объявлена где-то ещё и перебивает панель.

## Шаг 19. Финальная проверка

На `https://<домен>`, лучше в двух окнах (второе — инкогнито):

| № | Действие | Ожидание |
|---|---|---|
| 1 | Войти клиенткой (`+79210000010` или новая регистрация) | открывается «Мои записи» |
| 2 | Записаться: услуга → мастер → время → «Подтвердить запись» | «Записались, №…», запись в кабинете; время в кабинете совпадает с выбранным (сервер хранит UTC, показывает Москву) |
| 3 | Войти администратором, `/admin`, день записи | запись видна в списке |
| 4 | «Перенести» → новое время → «Перенести» | «Визит … перенесён на …» |
| 5 | Клиенткой: «Мои записи» и «Уведомления» | та же запись с новым временем, уведомление «Визит перенесён» |
| 6 | Записать номер записи и время. **Coolify → Redeploy** (без изменения кода) | развёртывание успешно |
| 7 | После деплоя обновить кабинет клиентки и `/admin` | запись на месте с тем же номером и временем; вход не слетел или повторный вход проходит |

Если на шаге 7 записи нет, база осталась внутри контейнера: проверьте **Persistent Storage** (том на `/app/storage`) и `SQLITE_PATH=/app/storage/nogotochki.db` в логах старта («База: …»).

Результаты — в дневник сборки: адрес, дословный текст экрана подтверждения, номер записи до и после повторного деплоя.

| Проверка | Результат |

| Лишнее наружу не отдаётся | после правки `.dockerignore`: `/README.md` → 404, `server/scripts` в образ не попадает |

**Что поправлено по итогам:**

- из `docker-compose.yaml` убраны `ADMIN_EMAIL=${ADMIN_EMAIL:-}` и соседние строки — та же ловушка, что ломала вход через Яндекс: пустое объявление перебивает значение из панели;
- `ports: "3000:3000"` заменён на `expose: "3000"` — порт больше не публикуется на сервере в обход прокси и HTTPS;
- `.dockerignore`: исключены `web/README.md` и `server/scripts/`.

**Запуск контейнера на своём компьютере** (порт наружу не публикуется, поэтому нужен второй файл):

```yaml
# compose.local.yaml — рядом с docker-compose.yaml, в git не добавлять
services:
  app:
    ports: ["3310:3000"]
    environment:
      - ADMIN_EMAIL=you@example.com
      - ADMIN_PASSWORD=придумайте-пароль
```

```bash
docker compose -f docker-compose.yaml -f compose.local.yaml up -d --build
```

Сервис — на `http://127.0.0.1:3310`.
