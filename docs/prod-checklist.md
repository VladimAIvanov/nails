# Приёмка на боевом адресе

Сокращённый прогон для <https://varvara-nails.ru>. Из 67 сценариев полного [чек-листа](test-checklist.md) отобраны те, на которые публикация повлияла на самом деле.

**Критерий отбора.** Переезд изменил четыре вещи, и только они: время теперь считает сервер со своим часовым поясом; страница приходит по защищённому соединению; переменные окружения заполнялись руками в панели и часть могла не доехать; запросы идут по сети и заметно медленнее. Сценарий попал в список, только если хотя бы одно из этого могло его сломать.

**Проверяет человек, в браузере, на боевом адресе.** Ассистент этот прогон не выполнял и выполнить не может: браузера у него нет, на сервер он не ходит. Ниже — список и причины, результаты заполняются руками.

**Результат писать дословно.** «Работает» — не результат. «Записался на 14:00, в кабинете показывает 11:00» — результат, с которым можно что-то делать.

---

## Перед прогоном

Два действия, без которых прогон не состоится.

**1. Наполнить прайс.** Сейчас в базе 0 услуг и 0 мастеров: рубрики есть, содержимого нет. Половина сценариев ниже про запись, а записаться не на что. Заводится из панели студии под учётной записью администратора.

**2. Скачать копию базы себе** — до всех остальных действий шага, потому что дальше пойдут пуши в основную ветку, а каждый пуш теперь уезжает на боевой сервер.

```bash
docker exec $(docker ps -qf name=^app-) sh -c 'cd /app/storage && sqlite3 varvara.db ".backup /tmp/copy.db"' 2>/dev/null || docker cp $(docker ps -qf name=^app-):/app/storage/varvara.db /root/varvara-$(date +%F).db
```

Затем забрать файл на свой компьютер (выполняется **у себя**, не на сервере):

```bash
scp root@159.194.255.54:/root/varvara-*.db .
```

Дата в имени файла обязательна: через месяц надо понимать, на какой момент это копия.

## Сценарии

| № | Сценарий | Что должно произойти | Почему в списке | Результат |
|---|---|---|---|---|
| 1 | **К-1** Регистрация | Форма принимает имя, телефон, пароль и согласие; человек попадает в кабинет | Сеанс выдаётся сервером и уезжает кукой. За прокси кука получает признак `Secure` только если сервер узнал прокси по `TRUST_PROXY` — переменная заполнялась руками в панели | |
| 2 | **К-4** Вход с верным паролем | Пускает, в шапке появляется имя | То же самое с другой стороны: если кука не ставится или теряется при переходе на защищённое соединение, регистрация пройдёт, а вход сразу после неё — нет | |
| 3 | **К-8** Путь записи целиком | Запись создана, в кабинете стоит **та же цифра времени**, которую выбирали | Главный сценарий на часовой пояс. Смотреть не на факт записи, а на цифру: расхождение обычно ровно на несколько часов | |
| 4 | **А-3** Время совпадает с кабинетом клиента | Одна и та же запись показывает одно и то же время в панели студии и в кабинете клиентки | Прямая сверка двух представлений одного момента. Если пояс где-то берётся у системы, разойдутся именно они | |
| 5 | **А-2** Записи дня: даты и фильтр | Фильтр «сегодня» показывает записи сегодняшнего дня по московскому времени | «Сегодня» считает сервер. При UTC на сервере вечерние записи уезжают в завтра | |
| 6 | **К-18** Поздняя отмена | До визита меньше, чем правило студии, — предупреждение о поздней отмене показывается **до** нажатия | Правило считается от «сейчас» на сервере. Сдвиг пояса делает предупреждение то преждевременным, то запоздалым | |
| 7 | **Д-2** Календарь визита | Скачанный файл открывается в календаре, время визита совпадает с кабинетом | Файл формируется сервером, время в нём — с указанием зоны. Ошибка видна только в чужом календаре | |
| 8 | **К-12** Удержание снимается при уходе со страницы | Ушли с подтверждения — окно снова свободно | Запрос на снятие уходит при закрытии страницы. Локально он успевал всегда; по настоящей сети может не успеть, и окно останется заблокированным | |
| 9 | **Б-9** Два клиента на одно окно | Второй получает отказ и список свободных окон, кнопка гаснет; двух записей на одно время не появляется | Окно между проверкой и записью стало шире на величину сетевой задержки — ровно то, на чём такие гонки и ловятся | |
| 10 | **Вход через Яндекс** (заменяет К-26) | Переход к Яндексу, согласие, возврат в свой кабинет уже вошедшим | Ключи приложения заданы в панели, адрес возврата сверяется посимвольно. При несовпадении Яндекс молча вернёт на главную неавторизованным | |
| 11 | **Отказ на согласии Яндекса** | Возврат на экран входа с текстом «Вход через Яндекс не завершён» | Ветка проверена запросами, но не глазами на живом Яндексе. Чтобы экран согласия появился снова, доступ надо отозвать в Яндекс ID | |
| 12 | **Б-7** Перебор пароля | После восьми неудачных попыток — «Слишком много попыток входа» | Пороги берутся из переменных окружения. Отдельно: за прокси адрес клиента виден только при верном `TRUST_PROXY`, иначе лимит считает **всех посетителей одним** и заблокирует чужого | |
| 13 | **Б-6** Пропуск не лежит в браузере | В хранилище браузера пусто, кука помечена `HttpOnly` и `Secure` | Признак `Secure` появляется только на защищённом соединении и только если сервер узнал прокси. Локально проверить это было нельзя | |
| 14 | **Б-11** Строгая политика безопасности страниц | Ни одной ошибки в консоли браузера | Смешанное содержимое: защищённая страница молча не покажет то, что грузится по открытому адресу. Плюс на страницах появились картинки — логотип и значок вкладки, — которых при прошлом прогоне не было | |
| 15 | **Б-1** Клиент открывает панель по прямому адресу | Отказ, чужих записей не видно | От переезда не изменилось ничего — и потому проверяем: адрес теперь публичный, и цена ошибки другая | |
| 16 | **К-25** Путь записи на ширине телефона | Сценарий проходится целиком | Раньше проверялось имитацией в браузере. Теперь есть настоящий адрес: настоящий палец толще курсора, мобильный интернет медленнее, клавиатура сама перерисовывает страницу | |
| 17 | **К-24** Молчащая первая загрузка | Пока данные едут — заглушки; отказ показывается текстом | Задержки стали настоящими, и промежуточное состояние теперь видно глазами, а не только в теории | |

## Что отложено и почему

Не потеряно, а сознательно оставлено за рамками: ответ на вопрос «что в этом изменилось от переезда» — ничего. Этот код на сервере работает ровно так же, как на машине разработки.

**Гость:** Г-2 фильтр категорий, Г-3 навигация и якоря, Г-4 шаг записи без услуги, Г-5 запись без регистрации, Г-7 кабинет по прямому адресу, Г-8 несуществующий адрес, Г-9 сервис не отвечает, Г-10 лендинг на ширине телефона.

**Клиент:** К-2 регистрация на занятый телефон, К-3 без согласия, К-5 неверный пароль, К-6 пустая форма, К-7 неудачный вход не выбрасывает вошедшего, К-9 запись из нескольких услуг, К-10 «любой свободный мастер», К-11 занятое время видно и недоступно, К-13 возврат на подтверждение, К-14 кабинет показывает только свои записи, К-15 перенос, К-16 отказ от отмены, К-17 отмена, К-19 «повторить», К-20 лист ожидания, К-21 профиль, К-22 абонементы и баллы, К-23 смена пароля закрывает сеансы, К-27 восстановление доступа.

**Администратор:** А-1 вход ведёт в панель, А-4 оформление визита, А-5 и А-6 запись поверх занятого, А-7 отмена, А-8 перенос, А-9 свои действия не создают уведомлений, А-10 и А-11 блокировка времени, А-12 новая услуга доходит до клиента, А-13 отключение услуги, А-14 и А-15 удаление услуги, А-16 снятая отметка убирает мастера, А-17 цена старой записи, А-18 подтверждение, А-19 панель на телефоне, А-20 владелица с двумя ролями.

**Безопасность:** Б-2 чужая запись по номеру, Б-3 чужие уведомления, Б-5 мастер без прав, Б-8 адрес возврата не уводит на чужой сайт, Б-10 роль себе не назначить.

**Дополнительно:** Д-1 устройства и входы, Д-3 регулярная запись, Д-4 ссылка «правила отмены», Д-5 имя мастера в сводке.

**Устарел:** К-26 вход через Яндекс на заглушке — заглушки в проекте больше нет, её место в списке заняли строки 10 и 11.

Отдельная оговорка про Б-2, Б-3, Б-5 и Б-10: они про безопасность и от публикации не зависят технически, но если захочется перестраховаться на публичном адресе — проходятся за пять минут и лишними не будут.
