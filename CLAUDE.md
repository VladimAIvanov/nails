# Паспорт сервиса онлайн-записи «Ноготочки»

## О студии

«Ноготочки» — небольшая студия маникюра и оформления бровей. Работает только по предварительной записи: вторник–суббота, 10:00–20:00; воскресенье и понедельник закрыто.

Сейчас дату и время визита мастер согласовывает с клиентом вручную. Сервис заменяет эту переписку: клиент сам выбирает услугу, мастера и свободное время.

## Цель сервиса

Дать клиенту записаться без участия мастера, а студии — сократить ручное согласование времени и исключить двойную запись к одному мастеру на одно время.

Результат считается достигнутым, если клиент проходит путь «услуга → мастер → свободное время → запись» сам, запись появляется в его кабинете и в панели администратора, а занятое время пропадает из доступных окон.

## Целевая аудитория

- **Клиенты студии** — записываются на маникюр, педикюр, наращивание, дизайн ногтей и оформление бровей, чаще с телефона. Им важно видеть реально свободное время у нужного мастера, не дожидаясь ответа в мессенджере.
- **Администратор студии** — ведёт прайс, мастеров, их графики и все записи; раньше делал это вручную.

## Роли пользователей

| Роль | Кто это | Доступ |
|---|---|---|
| Клиент | зарегистрированный пользователь | каталог услуг и мастеров, свободное время, создание, перенос и отмена **своих** записей, личный кабинет. Чужие записи не видит |
| Администратор | сотрудник студии | отдельный раздел `/admin`: услуги, мастера, расписание, блокировки времени, записи **всех** клиентов |

Мастер в первой версии — это данные (профиль, услуги, график), а не отдельная рабочая роль в сценариях проектной работы.

## Основные пользовательские сценарии

**Клиент**

1. Регистрируется или входит.
2. Выбирает услугу → мастера, который её оказывает → дату и одно из свободных окон.
3. Подтверждает запись; видит её в личном кабинете, а выбранное время исчезает из доступных.
4. Переносит запись на другое свободное время (не позднее чем за сутки до визита) — меняется время той же записи, новая не создаётся.
5. Отменяет запись — она остаётся в истории со статусом «отменена», время снова свободно.

**Администратор**

1. Входит и открывает раздел `/admin`; клиент туда не попадает даже по прямому адресу.
2. Добавляет, редактирует и отключает услуги и мастеров, настраивает связи мастер–услуга.
3. Задаёт график мастера и блокирует время (обед, личное время, выходной).
4. Видит записи всех клиентов, отменяет и переносит их.

**Конфликтный сценарий.** Два клиента выбирают одно и то же время у одного мастера. Первый создаёт запись, второму сервис отказывает и предлагает ближайшие свободные окна. Проверка выполняется на сервере и в базе, а не только в интерфейсе.

**Граничные сценарии.** Услуга не успевает закончиться до конца смены — окно не показывается. Окно попадает на блокировку — не показывается. Мастер не оказывает услугу — его нельзя выбрать. Перенос менее чем за сутки — отказ.

## Функции клиента

- регистрация и вход;
- каталог услуг с ценой и длительностью;
- выбор мастера среди тех, кто оказывает услугу;
- просмотр свободных дат и времени;
- создание записи;
- личный кабинет: ближайшие записи и история;
- перенос и отмена своей записи.

## Функции администратора

- защищённый раздел, доступный только роли «администратор»;
- услуги: добавление, редактирование, отключение;
- мастера: добавление, редактирование, отключение, закрепление услуг;
- расписание: рабочие часы мастеров, блокировки времени;
- записи всех клиентов: просмотр, отмена, перенос.

## Правила расчёта свободного времени и записи

- Свободное время вычисляется в момент запроса из графика мастера, длительности услуги, действующих записей и блокировок; готовый список слотов не хранится.
- Технический перерыв между записями не нужен: визиты идут встык.
- Запись целиком помещается в рабочее время мастера. Если мастер не успевает оказать услугу до конца смены, слот не показывается.
- Один мастер не обслуживает двух клиентов одновременно: две действующие записи к одному мастеру на пересекающееся время невозможны — это гарантирует база данных.
- Запись создаётся только на свободный слот; сервер проверяет это сам, даже если время пришло в обход интерфейса.
- Отменённая запись не удаляется, а меняет статус; её время снова доступно.
- Перенос меняет время существующей записи. Клиент может перенести запись не позднее чем за сутки до визита.
- Отключённые мастера и услуги не предлагаются при новой записи, но остаются в уже созданных.
- Клиент видит только свои записи, администратор — все.
- Время хранится в UTC, показывается и считается по часовому поясу студии (Europe/Moscow).

## Ограничения

- Без онлайн-оплаты: запись создаётся без предоплаты, расчёт — в студии.
- Одна студия, один адрес и один график студии.
- Демонстрационные данные вымышленные; реальные персональные данные в учебный сервис не вводятся.
- Стек: Node.js 22.13+ и встроенный SQLite, без внешних зависимостей; один процесс отдаёт страницы и API.
- В коде есть задел сверх обязательного объёма (лист ожидания, абонементы и баллы, регулярные записи, календарь, очередь уведомлений, вход через Яндекс). В обязательные сценарии и проверку проектной работы он не входит; новые функции сверх паспорта не добавляются без отдельного решения.

## Возможные риски

| Риск | Что может случиться | Как снижаем |
|---|---|---|
| Гонка за слот | два клиента одновременно занимают одно время | запрет пересечения в базе, отказ второму с подсказкой свободных окон |
| Ошибка часового пояса | окна сдвигаются на 3 часа, запись попадает в чужой день | всё хранится в UTC, график и показ — по поясу студии |
| Запись в обход интерфейса | время вне смены или в блокировку отправлено прямым запросом | сервер сверяет время с графиком и блокировками |
| Отключение услуги или мастера | ломаются старые записи и история | отключение вместо удаления; цена и длительность фиксируются в записи |
| Утечка доступа | клиент видит чужие записи или открывает `/admin` | проверка роли на сервере для каждого запроса |
| Неоднозначная длительность дизайна (15–30 мин) | окно рассчитано коротким и наезжает на следующую запись | в расчёте берётся верхняя граница — 30 минут |
| Разрастание объёма | ИИ-ассистент добавляет функции вне задания | паспорт — источник требований; всё сверх него — только по отдельному решению |
| Потеря данных при деплое | база пересоздаётся при обновлении | файл SQLite на постоянном хранилище, миграции применяются при запуске |

## Как устроен репозиторий

| Папка | Что это |
|---|---|
| `server/` | API и база: Node.js + SQLite; миграции в `server/migrations`, демо-данные в `server/src/seed.js` |
| `web/` | клиентский интерфейс и админ-панель (`web/admin`) |
| `site/` | прототип экранов (артефакт проектирования, кодом не используется) |
| `docs/` | схема базы, журнал разработки, чек-лист тестов, требования к развёртыванию |

Команды запускаются из `server/`: `npm run migrate`, `npm run seed`, `npm run reset`, `npm start`. В PowerShell — через `npm.cmd`.
